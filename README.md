# playlist

A desktop player for YouTube playlists. You paste a link and it plays the
music.

Built with [MyGo](https://mygo.egoist.dev) for the native window and
[Onevra](https://oneo-me.github.io/onevra/) for the controls. No webview, no
browser engine.

![Home](docs/screenshots/home.png)

## What it does

- Reads a playlist from YouTube Music, or any playlist on YouTube: title,
  artist, album, artwork and length for each track.
- Plays the audio. The video never loads.
- Runs a queue with shuffle and repeat.
- Reopens on the playlist you had, with the track you were hearing at the
  place you stopped.
- Keeps the tracks on disk, so the second open of a playlist needs no network.
- Counts what you listened to: plays per day, and the tracks played most.
- Shows what plays in Discord, and scrobbles to Last.fm when an account is
  connected.
- Hides to the notification area when you close the window. The tray brings it
  back, and the media keys work from any app.

Right-click a playlist in the sidebar to delete it. The app asks first.

**Start a mix** on the player builds a mix around the track that is playing: an
endless queue of tracks like it, generated by YouTube. It needs no account,
because a mix is built from the track, not from your history.

## Requirements

You need two programs on your PATH. The app tells you which one is missing.

| Program | What it does |
|---|---|
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | finds the audio of a track |
| [ffmpeg](https://ffmpeg.org) | decodes the stream into PCM |

The playlist metadata comes from InnerTube, which the app talks to directly.

## Running it

```powershell
go tool mygo dev      # runs the app, rebuilding on every change
go tool mygo build    # packages the app in build/
```

Build with `mygo build`, not `go build`: the MyGo build is what makes a Windows
executable a GUI app with an icon and an installer, rather than a console
program with neither. `docs/shipping.md` says what each one produces.

## Layout

```
main.go                 entry point: calls src.Run()
src/                    the interface, one package
  app.go                state, window, what the app does
  shell.go              sidebar, page frame, room for the player bar
  page_*.go             one file per page
  playerbar.go          transport, place in the track, volume
  widgets.go            type roles and the pieces pages are built from
  theme.go              space, type, tracking, leading, motion
  surfaces.go           the faces the app paints
  assets.go             Inter, embedded
internal/
  music                 Track, Playlist
  innertube             the InnerTube client and its parser
  ytdlp                 resolves the audio of a track
  ffmpeg                decodes into PCM for MyGo's audio package
  player                queue, shuffle, repeat, autoplay
  playlist              picks the reader that knows the playlist
  library               what the app remembers between runs
```

## Three things to know before changing it

### The view reads state, it never writes it

The engine posts events on a channel. The window applies them on the thread
that draws. A field the engine writes is never read while another goroutine
writes it.

### Every size comes from one scale

Distances are multiples of the theme's spacing, sizes of its font size, corners
of its radius. Pages name a role (`pageName`, `body`, `caption`) instead of a
number. Two tests parse the source and fail a page that writes `t.Rem(1.5)` or
`ui.Hex("#f00")` by hand.

### The lock is not reentrant

`a.mu` guards the state the engine writes. A method that holds it must not call
one that takes it again, or the second Lock never returns and the window
freezes. `apply` hands the tray what it needs instead of letting the tray call
back. One test runs that path on a deadline; another parses the source for the
pattern.

## Tests

```powershell
go test ./...                     # logic and views
go test -tags e2e ./...           # real playlists, real audio
go test ./src/ -run TestDrawPages # writes a picture of every page
```

The design tests fail on a size or colour written by hand, on a text role under
12 DIPs, on a flat type hierarchy, and on anything that runs under the header
or into the player bar.
